# Задание 1. Разработка функционала с применением библиотеки потоковой обработки данных

**Задача.** Создайте систему обработки потоков сообщений с функциями блокировки пользователей и цензуры сообщений. Разверните систему с использованием Docker-compose и настройте необходимые топики Kafka.

## Подзадача 1. Блокировка нежелательных пользователей

Реализуйте поток обработки сообщений, в котором пользователи смогут блокировать других пользователей. Для этого:

- Создайте отдельный список заблокированных для каждого пользователя.
- Этот список должен храниться в персистентном хранилище:
  - Java: persistent state store
  - Python: table
  - Go: group table
- Реализуйте автоматическую фильтрацию: сообщения от нежелательных пользователей не должны доходить до получателей.

## Подзадача 2. Цензура на слова

- Создайте список запрещённых слов, который можно динамически обновлять.
- Добавьте компонент, обрабатывающий поток сообщений и удаляющий или маскирующий запрещённые слова.
- Все сообщения должны проходить через цензуру перед отправкой получателю.

## Инфраструктура

- Используйте Docker-compose для развёртывания.
- Подготовьте топики Kafka:
  - `messages` ― входящие сообщения,
  - `filtered_messages` ― сообщения после обработки,
  - `blocked_users` ― данные о заблокированных пользователях.

## Тестирование

Создайте тестовые данные для проверки блокировки и цензуры сообщений в топиках.

## Инструменты

- Язык: Java, Python или Go.
- Библиотеки: Kafka Streams, Faust или Goka.

## Как должен выглядеть результат

Выполненное задание должно включать:

- Docker-compose файл, который развернёт инфраструктуру для выполнения задания.
- Рабочий код, в котором:
  - сообщения фильтруются по спискам блокировок и запрещённых слов,
  - есть логичная структура и понятные комментарии.
- Файл README.md с:
  - описанием классов и логики работы приложения,
  - инструкцией по запуску проекта,
  - инструкцией по тестированию,
  - тестовыми данными, которые надо отправить в топики для проверки.

# Задание 2 (дополнительно). Анализ и агрегирование сообщений с помощью ksqlDB

**Задача.** Реализуйте аналитику для системы обмена сообщениями с помощью ksqlDB.
Считайте, что сообщения в JSON-формате содержат поля `user_id`, `recipient_id`, `message` и `timestamp`.

## Подзадача 1. Анализ сообщений в реальном времени

- Создайте поток в ksqlDB (`messages_stream`), который будет принимать входящие сообщения из Kafka.
- Реализуйте таблицы, подсчитывающие:
  - общее количество отправленных сообщений;
  - количество уникальных получателей сообщений.

## Подзадача 2. Сбор статистики по пользователям

- Создайте таблицу `user_statistics` для агрегирования данных по каждому пользователю:
  - сообщения, отправленные каждым пользователем;
  - количество уникальных получателей для каждого пользователя.
- Сохраняйте данные в таблице для последующего использования.

## Инфраструктура

- Используйте Docker-compose для развёртывания ksqlDB.
- Подготовьте топики Kafka:
  - `messages` ― входящие сообщения,
  - `user_statistics` ― результаты агрегирования.

## Как должен выглядеть результат

В системе:

- Пользователи могут выполнять запросы к ksqlDB для получения статистики.
- Отображаются данные в реальном времени на основе входящих сообщений.

Выполненное задание должно включать:

- Docker-compose файл, который развернёт инфраструктуру для выполнения задания.
- `ksqldb-queries.sql` с выполненными запросами:
  - создание исходного потока;
  - таблицы общего количества отправленных сообщений;
  - таблицы с числом уникальных получателей для всех сообщений;
  - таблицы с количеством сообщений, отправленных каждым пользователем;
  - таблицы для агрегирования данных по каждому пользователю.
- Файл README.md, в котором есть:
  - инструкция по запуску и тестированию,
  - тестовые данные и команды для отправки их в топик,
  - тестовые запросы в ksqlDB для проверки:
    - общего количества отправленных сообщений;
    - числа уникальных получателей.
